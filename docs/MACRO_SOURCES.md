# マクロ値 (kcal / P / F / C) の出典と照合

> 最終更新: 2026-10-22
> 関連: [IA-identity-spec.md](./IA-identity-spec.md) v1.11 / [NUTRITION_NOTES_SOURCES.md](./NUTRITION_NOTES_SOURCES.md) (豆知識の出典照合。こちらはマクロ値)

DB の食べ物の数値を、**一次出典と機械で突き合わせる**仕組みとその記録。
きっかけは「アンカーと新規の種類の値は記憶ベースで、一次出典とは未照合」だったこと (ROADMAP 2026-10-22)。

## 2. 仕組み

```
Excel (文科省) ──scripts/seibun_extract.py (標準ライブラリのみ・python3 -I)──▶ seibun-2023.json (抜粋)
                                                                              │
constants/identity/seibun-links.ts (DB の key ⇔ 食品番号) ──┐                  │
constants/identity/external-checks.ts (公式・USDA)          ├─▶ utils/seibun-compare.ts ──▶ seibun-verification.test.ts
                                                            ┘   scripts/seibun-report.ts (一覧)
```

- **再生成**: `bun scripts/seibun-sync.ts <第2章xlsx>` (ダウンロードは専用の空ディレクトリへ。外部ファイルは `python3 -I` で読む)
- **一覧**: `bun scripts/seibun-report.ts` — 全項目の DB 値 / 成分表値 / 逆算した1個あたりの重さ / 範囲外の理由
- **テスト**: `expo/constants/identity/seibun-verification.test.ts` (範囲外が増えると落ちる。凍結リスト `KNOWN_SEIBUN_DEVIATIONS` は現在**空**)

### 照合の2種類 (`weight`)

| | 比べるもの | 対象 |
|---|---|---|
| `known` | 100g (ml は密度を掛けて) あたりの kcal / P / F / C。許容は kcal ±25%、P/F ±35% (または絶対 2.5g)、C ±35% (または 3.5g) | g / ml 基準の食品 |
| `assumed` | **組成 (P/F/C のエネルギー比)** だけ。各 12 ポイント以内 | 個数基準 (1個・1枚・1本)。重さは一次出典が無い目安なので kcal の絶対値は比べない。逆算した「1個あたり g」を人が見て妥当か判断する |

- **調理で加わるもの** (焼き油・たれ・ソース) は成分表の素材値に無い。`extra` で DB の1食ぶんに上乗せして比べる (例: ステーキ 150g の焼き油 5g)。
- **出典の値が内部で食い違うとき** (kcal が P/F/C から30%以上外れる) は、組成を比べない (`skipped`)。春巻きがこれ (kcal 221 に対し脂質 19.3g)。DB のほうが整合している。
- 対応表の食品名は、成分表の食品番号が指す名前に**含まれる**ことをテストが照合する (番号の取り違え防止)。

## 3.5 料理 (%基準) のチェーン公式との照合 (2026-10-22 追加)

**US で照合していないもの**: ① 食材のうち `us_sausage` / `us_plant_milk` / `us_protein_bar` / `us_coffee_drink` / `us_smoothie` / `us_cocktail` (理由は `USDA_UNLINKED`) ② 料理の 34件 (上記) ③ **チェーン公式の栄養表との照合** — チェーンの公式サイトは JavaScript で描画され取得できなかった。USDA の Branded Foods (商品ごとの表示値) は API なら引けるが `DEMO_KEY` の上限 (10回/時間) で足りない。API キーの取得 (無料・メール登録) が要る。**チェーン基準の料理 (Big Mac・Chipotle・Olive Garden 等) の公式値との照合は未実施**。

## 4. 照合していないもの (できないもの) と理由

1. **%基準の料理のうち 75行** (§3.5 の26行を除く) — チャーハン・オムライス・ラーメンの大半・つけ麺・担々麺・焼そば・冷麺・そば・そうめん・パスタ・寿司・鍋・弁当の一部・ピザ・中華おかず・和風おかず・ガパオ・ビビンバ。チェーンの公式が取れなかったもの: **かつや** (検索結果なし)、**はなまるうどん** (公式PDFの URL が HTML を返し取得不可)、**丸亀製麺** (栄養成分の一覧が見つからない)、**リンガーハット・餃子の王将** (数値なし)、**大戸屋** (証明書の期限切れで個別ページ不可)、**サイゼリヤ** (アレルギー情報ページに数値が出ない)、**スシロー** (一覧PDFなし、店舗ページに1皿の値のみ)、**日高屋** (kcal のみ)、**ケンタッキー** (公式の栄養成分表の所在が見つからない)。**次の候補**: ラーメン・パスタ・寿司は、チェーンが公式の一覧を公開していても検索で拾えないものが多い。個別にURLを教えてもらえれば、PDFを取得して同じ方法で読める。」
2. **個数基準の kcal の絶対値** — 1個の重さに一次出典が無い。組成だけ照合している。公式の重量が取れたものは `known` に上げる (ナゲットは公式が1食の値なので直接比較)。
3. **ケンタッキーのオリジナルチキン (フライドチキン 1ピース 230kcal)** — 公式サイトの栄養成分の取得が **タイムアウト**で未取得。第三者サイトでは 218〜237kcal。公式を取れたら `external-checks.ts` に足す。
4. **セブン・ファミマ・ローソンの商品、各チェーンの他メニュー** — 未取得。
5. **US の食品の大半** — USDA は卵・ベーコンのみ。同じ API (`DEMO_KEY`) で取れるので、US 食材は機械的に広げられる。
6. **うな丼・肉まん・あんまん・生姜焼き (新規の種類)** — 成分表の素材 + 重さの仮定で組成は照合済み (肉まん・あんまんは成分表に食品あり)。うな丼は料理単位で値が無く未照合。

## 5. 追加するとき

- **新しい Identity / 種類を足すとき**: `seibun-links.ts` に対応を足す (g 基準は `K`、個数基準は `A`)。成分表に無ければ `external-checks.ts` に公式・USDA の値と URL・取得日を書く。**どちらも無いなら、`unit-anchors.ts` の目安だけで通ることになる。その場合は本書 §4 に「未照合」として足す。**
